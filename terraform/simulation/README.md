# Offline governance desired-configuration demonstration

This is a separate, **provider-free, resource-free, data-source-free** root. It imports only `../modules/simulated_governance`. It does not import, alter, or deploy `terraform/poc`, configure a remote backend, read credentials, run provisioners, or measure compliance. Terraform >=1.14,<2 is required (tested with 1.14.6). No provider installation is needed.

Input is a frozen Phase 5 CLI proposal in an existing ignored run directory. `policy_version=1.0.0` selects its baseline; `2.0.0` (default) selects its candidate. Ten module instances calculate per-account desired assignments, centrally inherited baseline, environment-specific approval requirements and evidence freshness. Inactive accounts still have desired assignments; the Python rollout explicitly defers applying them. The eleventh account's later onboarding remains a Python simulation, not a claim that the ten-account Terraform plan covers onboarding.

See the [five-minute runbook](../../docs/POLICY_ROLLOUT_DEMO.md#five-minute-terraform-and-rollout-walkthrough) for executable fmt/init/validate/plan/show/comparison commands and expected output. Plans change **outputs only**, so Terraform may suggest applying to persist outputs. Do not apply: it is unnecessary and outside this demo's authorization. Init uses no remote backend; all saved plans/JSON belong under ignored `artifacts/policy-rollout/`.

`python -m governance.simulation.terraform_plan` verifies the entire planned output against the frozen CLI proposal, including its digest and requested version, and rejects provider/resource-bearing plans. It verifies state checksum/domain contracts using the existing CLI reader. Terraform itself checks baseline/assignment preconditions; Python performs the complete model/checksum comparison. This is semantic consistency checking, not proof of authentic Terraform execution or an authenticated approval. A local file owner can forge local artifacts.

This optional check does not alter or gate existing CLI commands. The runbook places it before simulated approval; automation enforcing this check would require a separate design. Real Terraform planning establishes desired configuration only; simulated AFT/customization results and compliance observations remain Python outputs. No live application publication path is added.
