## Repeatable verification

Run the commands in [README validation](../README.md#validation) and [Resource Compliance Operations](RESOURCE_COMPLIANCE_OPERATIONS.md#local-validation). Additionally:

```sh
.venv/bin/python -m unittest discover -s terraform/enterprise/tests -v
terraform fmt -check -recursive terraform
terraform -chdir=terraform/poc validate
```

POC mock-provider plans validate configuration boundaries only; they do not prove AWS compatibility. Real cloud activation needs a reviewed Lambda update, real protected data approval, a one-resource Amplify environment-setting plan and authenticated browser verification. Do not mark these pending items implemented and verified until actual evidence exists.

## Hosted validation evidence

[PR #20 CI](https://github.com/bosphorus-cloud-labs/northstar-airlines-aws-landing-zone/actions/runs/42057582526) passed Governance checks and Frontend checks for the proposed resource console. This establishes hosted validation, not protected publication or cloud activation. The refreshed private AWS plan proposed one existing Lambda package update, zero creates/destroys and no changes to authentication, IAM, API, storage or hosting. No apply or data publication was performed during this validation.

The one-file negative-observation rehearsal changes only Booking API metadata tokens from `required` to `optional`: all 150 Python tests, 56 frontend tests and the generated API contract check pass while actual source evaluation reports 6 compliant / 2 noncompliant / 1 unknown / 1 stale. Unit scenarios and frontend test examples are deliberately frozen under `tests/fixtures/`; they are not runtime fallback data.
