# Governance requirements traceability

The POC demonstrates **environment-specific governance → real provider-free Terraform planning → multi-account application reporting**. Resource observations are one input to that governance flow, not a replacement for Terraform or the account lifecycle examples.

Each classification describes the evidence and scope in its row. **Implemented and tested** means executable code/configuration with completed checks; it does not imply every cloud acceptance step has passed. **Simulated and tested** means synthetic account/resource effects. **Architecture/design only** means an enterprise operating model or reference configuration without live execution. **Missing or incomplete** identifies acceptance that has not been demonstrated.

## Verification commands

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m unittest discover -s terraform/enterprise/tests -v
npm --prefix frontend run api:check
npm --prefix frontend run typecheck
npm --prefix frontend test
npm --prefix frontend run build
terraform fmt -check -recursive terraform
```

The Python suite executes real provider-free Terraform commands and full parity checks. POC mock-provider plans are an additional offline configuration check, **not** proof of real AWS deployment compatibility. See [README validation](../README.md#validation) for lint, packaging and POC validation prerequisites.

## Hosted evidence

[Resource-console acceptance](RESOURCE_CONSOLE_ACCEPTANCE.md) records actual baseline and regression publication, exact source/run links, the one-setting Amplify activation and authenticated browser checks. The previous false-green run is explicitly excluded from publication evidence. The approved Git-revert publication restored the original content at generation 3. Both immutable snapshots and all three audit events were strongly verified; the authenticated application displayed the correct restoration.

The compatible Lambda package was rebuilt with the same checksum as deployed. It preserves the read-only role, authentication, original catalogue and historical snapshots. The resource console reports complete ten-account Terraform receipt parity across all four environments, independently from synthetic compliance evidence.

## Coverage-review verification

The coverage checkout passed 153 Python tests, 57 frontend tests, 12 enterprise-reference tests, 30 Terraform mock-provider plan cases, API contract checks, TypeScript, production build, scoped Ruff, dependency checks, compilation and Terraform formatting/validation. The additional organization-wide case uses real provider-free Terraform plans across all ten accounts/four environments; unrelated controls remain unchanged.

Actual Git changes and environment-targeted Production 24→12-hour freshness are tested independently. The latter produces stale evidence, not an invented encryption violation. See the operational guide for exact commands and an offline fallback. Green plans and local simulations do not establish cloud execution; the acceptance record identifies each completed live step separately.
